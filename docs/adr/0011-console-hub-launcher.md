# ADR-0011: Console hub launcher

**Date:** 2026-06-18
**Status:** Accepted

WingletReader's home surface becomes a console/Walkman-style **hub**: the whole window reads as one retro-gadget **device face** presenting five equal **tiles** (Read · Import · RWW · Make Video · Settings) in a centered symmetric row, with a fixed **LCD detail strip** below that describes the focused tile. The hub replaces both the former Library-as-home and the `ShellTopBar`. This supersedes ADR-0009's *global-chrome* decision (top bar + Library-as-home) while keeping ADR-0009's *launched-mode* model: Reader and Transmute open *from* tiles/content, they are not static global destinations. The driver is the maintainer's complaint that the app buries its core feature (speed-reading) under management chrome and "looks generic and unfinished"; the hub makes reading the star and gives the app a real device identity of-a-piece with the splash.

This decision covers **Phase 1 only**: the hub plus a global retro-gadget visual language. In-reader complexity (Quick Settings / Profiles / Palettes / triplets / scrubber) and inner-screen structural restructure are explicitly deferred to later passes. Full charter and grill history: `.scratch/done/hub-redesign/`.

## Considered Options

- **Keep ADR-0009's minimal top bar, add nothing.** Rejected: does not fix the "looks generic / core feature buried" pain that motivated the work.
- **Reading-first shelf home, or a decluttered-library home, or empty-first-run onboarding.** Rejected by the maintainer in favour of a block/console launcher with all main destinations side by side.
- **Hero Read tile + satellite tiles, or a two-tier read/utility split, or folding Import into Read (4-tile roster), or Settings as a corner gear (3-tile roster).** Rejected: the maintainer chose **five equal tiles**, with Read's primacy coming from position (leftmost, default focus) and direct resume, not from a larger tile.
- **A literal letterboxed device frame, or a fluid full-bleed grid.** Rejected: a letterboxed emulator wastes space when maximized and reads as a toy; full-bleed loses device containment. Chosen: the **whole window is the device face**, a contained max-width surface centered on a darker desk backdrop.
- **Clean-modern device aesthetic (Teenage-Engineering-style)** which would retire the dove/red-serif brand. Rejected: the redesign leans *into* the existing brand (cobalt dove, red serif wordmark, splash world).

## Decision

1. **Routing.** Add `hub` to the `AppView` union; `NavigationContext`'s default view flips from `'library'` to `'hub'`. Reader and Transmute remain route-backed but launch from tiles/content (ADR-0009 retained).
2. **Layout.** Whole-window device face: a centered, max-width (~1150px) console surface on a darker desk backdrop, with a minimum window size and centered reflow only at very narrow widths. Five equal, square tiles in one centered row, symmetric about the middle tile, Read leftmost. A single fixed LCD detail strip sits below the row and swaps content to the focused tile.
3. **Interaction.** Mouse-first and click-through: hover focuses a tile and updates the LCD, a click anywhere on a tile activates it. Keyboard is a secondary accessible fallback (roving `tabindex`, arrow keys, Enter/Space to activate, Esc returns focus to Read). The focus ring reuses the existing `--brand-focus` token. All motion honours `prefers-reduced-motion`.
4. **Tile behaviours.** Read resumes the last session directly (`resumeReader()`), else opens Library; Import opens its own new view (`ImportPanel`); RWW opens the Console; **Make Video** opens a dedicated launchpad offering source selection — choose a saved text *or* paste/upload new text (no forced Library save) — both routing into `TransmuteView` (there is no persisted last-project, so the tile cannot reopen one); Settings opens global settings. Library's tab bar dissolves (Library = the text list), Library defers to Import for adding texts (empty Library guides straight to Import), and Chapters stays the contextual per-text view.
5. **Persistent Home control.** A small dove mark fixed top-left on every inner screen (including Settings sub-pages) returns to the hub; it is additive to any screen-local back. The Reader is exempt and keeps its own full-screen chrome and Back.
6. **Visual language.** Sharp-edged industrial (single radius-0 system, bezel depth via insets and tinted — never pure-black — shadows). Cobalt/sky becomes the single interactive accent (replacing the white `--accent`); the brand red is reserved exclusively for the live serif **"WingletReader"** wordmark (new `--brand-red` token). The pixel/LCD motif is confined to the detail strip, which is a recessed dark phosphor screen in **both** themes. Dark is the signature finish; light is a warm-paper "cobalt + cream" device finish. The **hub** identity is deterministic and must **not** branch on the legacy `logo_style` setting (per the UI-overhaul issue 10 ruling); see the 2026-06-19 amendment below for the one sanctioned exception (the Reader idle logo). The dove uses a maintainer-supplied vector/hi-res asset (a 432px splash sprite frame is an acceptable interim). The splash→hub transition is visual continuity (same dove, same dark cobalt world, one-time settle) rather than a cross-window animation.

## Consequences

- **The hub gates the Phase 4 alpha invite.** The maintainer chose to ship the hub in the *first* alpha build, so the invite is blocked on Phase 1 landing; the first tester impression is the retro-gadget hub. Sequencing recorded in `CONTEXT.md`.
- `ShellTopBar` is removed; the shell test that asserts the top bar must be updated to assert the hub (Tier C fallout, expected). The resume chip and Library tab bar are absorbed into the Read tile's LCD and the new Import view respectively.
- Tier A is untouched: the JSON store, frozen identifiers, the ADR-0008 settings contract, and the reading engine/playback math are not modified. This is a Tier-B presentation/structure change.
- The `--accent` shift from white to cobalt ripples app-wide; downstream surfaces inherit the new tokens but keep their current structure in Phase 1.
- Dead `.showcase-*` CSS rules are candidate cleanup during the token work.
- **Implementation discipline.** The hub and visual work run under two design skills with split, non-overlapping roles: `design-taste-frontend` sets net-new direction (its dials forced **low** to honour the locked symmetric console; serif reserved to the wordmark), and `redesign-existing-projects` audits inherited surfaces for generic-AI patterns and holds the stack veto (Electron + vanilla `index.css`, no Tailwind/Motion/new dependencies). Canonical statement and per-issue split: `.scratch/done/hub-redesign/issues/README.md`.

## Amendment — 2026-06-19: Reader idle logo is a protected brand surface

Decision §6's "identity is deterministic, must not branch on `logo_style`" rule is **scoped to the hub identity and the favicon/showcase paths** — not to the Reader. The **Reader idle screen logo** (the idle dove) is a deliberate brand surface on the same footing as the Splash showcase (maintainer call during slice-01 development, `81eff20`). It **does** branch on the stored `logo_style` setting (`modern` → `assets/logo-modern.png`, `classic` → `assets/logo-classic.png`), with `AppShell` mirroring `logo_style` onto `body[data-logo-style]` so the per-style blend treatment resolves. This reverses UI-overhaul issue 10's removal of the idle dove for this surface only. Agents must not re-flatten the Reader idle dove to a plain text wordmark or fold it back under the deterministic-identity rule without a new maintainer decision. Domain entry: `CONTEXT.md` → "Reader idle logo (idle dove)".
